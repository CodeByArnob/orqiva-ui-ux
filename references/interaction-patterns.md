# Interaction Patterns

Define relevant states: default, hover, focus, pressed, selected, disabled, loading, empty, error, success, offline, permission denied, partial completion, and destructive confirmation.

Buttons need action-specific labels and distinguish primary, secondary, tertiary, and destructive actions. Prevent duplicate submissions where appropriate.

Navigation needs active-location indication. Links navigate; buttons perform actions. Avoid inert clickable-looking elements.

Dialogs need clear titles/actions, dismissal behavior, focus management, and mobile adaptation.

Use inline feedback for field issues, banners for page status, and transient notifications for non-blocking feedback. Critical errors must remain understandable. Motion should explain transitions and respect reduced motion.
