# Mobile Platforms

Shared: prioritize main task and thumb reach; support variable screen sizes and text scaling; handle permissions contextually; account for keyboard, safe areas, system bars, and gestures; provide loading/failure/offline feedback.

Android: follow Material and Android conventions where appropriate. Respect system bars, edge-to-edge, back navigation, adaptive layouts, touch feedback, and dynamic text. Compose components should have clear state ownership.

iOS: respect safe areas, navigation, system controls, typography, sheets, gestures, and accessibility.

Flutter: use adaptive capabilities for cross-platform products, centralize theme tokens, separate widget composition from business state, and test text scaling, keyboard, safe areas, and navigation.

React Native: respect native platform differences and validate on target platforms.

Check first-screen clarity, discoverable primary action, usable touch targets, keyboard overlap, safe areas, states, localization, offline behavior, and back navigation.
