# UX Architecture

Identify audiences, top user jobs, frequent and high-risk tasks, context of use, trust/privacy expectations, and success criteria.

Map each journey: entry, goal, required information, action, feedback, completion, and recovery.

Group information by user mental model, not database schema. Distinguish global navigation, local navigation, contextual actions, and destructive actions.

Choose navigation deliberately: bottom navigation for a small set of mobile destinations; rail/drawer for larger hierarchies; tabs for peer views; breadcrumbs for deep web hierarchy; sidebars for desktop workspaces; command palettes for expert workflows.

Forms need explicit labels, appropriate input types, useful validation, preserved input after errors, and clear completion feedback. Never use placeholder text as the only label.

Use concise microcopy. Errors should say what happened and how to recover. Do not create screens without a user or system purpose.

For substantial work produce screen inventory, navigation map, primary journey, component inventory, state inventory, responsive notes, and accessibility considerations.
